> [项目总审计与路线图](PROJECT_AUDIT_AND_ROADMAP_CN.md) ·

本目录明确支持两条不能混写结论的路线：

- **A：公平物理后端对比**——固定 SIM1 资产和轨迹，比较 Newton 与 Genesis IPC；
- **B：成功导向 Genesis Demo**——保留同一任务结构，但允许按当前布料状态修正抓点与折叠轨迹。

当前默认以 B 为主线、A 为对照。标注为“同轨迹”的结果不能使用 B 的状态自适应
修正，标注为“Genesis 折衣 Demo”的结果也不能宣称是严格的 Newton 后端复现。

保持不变：

- SIM1 的 Acone 双臂 URDF；
- `scale_fold_shirt_in_domain/episode_000000` 的 19 维、60 Hz 轨迹；
- SIM1 的 `short-shirt.usdc` 三角网格及平面内初始位姿；
- 桌面和机器人基座的世界坐标。

发生变化：

- Newton 的三角形/边弹簧布料改为 Genesis `FEM.Cloth` 壳单元；
- 接触、自碰撞和摩擦改由 IPC barrier contact 求解；
- 公开 Newton 初态存在桌面穿透，IPC 版先将衣服抬至 z=0.93 并预沉降；
- 为满足该双层网格的无穿透距离，IPC 壳厚/接触阈值基线为 0.2 mm；
- 自然抓取基线只使用实体夹爪接触；另提供显式标注的虚拟绑定诊断模式。

注意：SIM1/Newton 的 19 维轨迹按“完整左臂链、左夹指、完整右臂链、右夹指”
排列。当前 Genesis legacy URDF 解析器恰好保持相同顺序，但运行脚本仍按关节
名称显式校验并生成映射，避免以后更换解析器或资产后静默错位。

官方 parquet 的 `action[6/13]` 不是直接的 URDF 关节值，而是被 SIM1
`sim2real.py` 乘了负比例：物理夹指 `q=0.001`（闭）打包成约 `0`，
`q=0.044`（开）打包成约 `-3.24`。因此解码公式是
`openness=raw/-3.24`，再映射回 `q=0.001+0.043*openness`。这与帖子中直接
名为 `gripper_close` 的控制量不是同一层表示，不能把符号语义直接套过来。

## 运行

快速结构测试（60 帧，不录视频）：

```bash
./run.sh --frames 60 --no-record
```

快速调试预设（自动使用 1300 顶点/2500 面短袖和较低 IPC 迭代上限）：

```bash
./run_fast.sh --frames 180 --no-record
```

快速预设仍保持 `dt=1/60 s`，不会通过跳过轨迹帧来伪加速。当前 180 帧基准：

- 原始 7021 顶点/13767 面 + 快求解器：平均约 1.99 FPS；
- 低模 1300 顶点/2500 面 + 快求解器：平均约 3.91 FPS；
- 低模的原始顶点最近邻映射保存在同目录的 `short-shirt-2500f.vertex_map.npz`。

可用 `FAST_FACES=8000 ./run_fast.sh ...` 选择中高分辨率调试网格。2500 面模型
适合查轨迹和程序错误，但它在第一次下摆抓取区的原始顶点映射误差约为
7--22 mm，并会把右手背面层的三个抓点合并成一个顶点，不能用来判断双层
下摆是否稳定夹持。8000 面模型的抓点平均映射误差约为 3.6 mm。

快速预设用于调试抓取时序和轨迹，不作为最终 Newton/Genesis 物理质量对比结果。

完整录制：

```bash
./run.sh
```

`run_three_folds_arc.sh` 默认启用四路同步录制。除主视频外，会生成
`*_overhead.mp4`、`*_shirt_bottom.mp4`、`*_right_grasp.mp4`，并合成为
`*_multiview.mp4`。四宫格顺序固定为：左上整体斜视、右上俯视、左下从
短袖下侧看向领口、右下跟随右 TCP 的抓取近景。直接调用 Python 时可用
`--record-multi-view` 启用相同功能。

前台 Viewer：

```bash
./run.sh --viewer --no-record
```

只验证“抓点是否会随机械臂抬起”的运动学诊断：

```bash
./run_kinematic_grasp.sh
```

不使用任何锚点，只测试夹指接触、夹紧压力与摩擦能否完成第一次抬升：

```bash
./run_contact_grasp_test.sh
```

该脚本默认使用 8000 面模型；可用 `CONTACT_MESH_FACES=2500` 临时退回快速
诊断模型。运行并录制完整第一折（第 332 帧释放，录到第 380 帧）使用：

```bash
./run_first_fold.sh
```

该测试将机械臂和夹指作为严格回放公开轨迹的规定运动刚体边界，并将约 1 mm
的记录闭合位置最多推进到 URDF 下限 0 mm 来提供法向夹紧力，绝不允许负 q
或夹指越过正常零位。这与 Genesis 官方 IPC 布料夹爪
示例采用“超闭合位置目标”的思路一致；IPC 仍负责夹指—布料防穿透、接触
反力和摩擦，代码没有绑定或直接改写任何布料顶点。它适合比较布料后端和
轨迹效果，但不用于评价夹指电机动力学。JSON 中的 `contact_grasp_summary`
会记录抓取附近布料节点和 TCP 的最大抬升量，用于区分稳定夹起与机械臂空抬。
即使通过 `run_fast.sh` 使用低模，接触抓取测试也保留 1 mm 的 IPC 平移收敛
容差；普通快速预览的 20 mm 容差远大于夹布接触尺度，不能用于判断抓取成败。
当前预设还给右手增加 0.25 mm 的额外闭合补偿，使左右第一次闭合的最终目标
均约为 0.85 mm；最终目标仍受 Acone URDF 的 0 mm 下限约束。

运动学硬绑定模式会关闭接触和重力，以避免外部硬改节点状态破坏 IPC CCD。
它能验证资产、TCP 坐标、抓点映射和轨迹时序，但不能用来评价桌面接触、
自碰撞或最终折叠质量。

脚本按 UUID 固定 RTX 5070 Ti（CUDA 与 `nvidia-smi` 在这台双显卡机器上的数字顺序相反）。可通过 `GENESIS_GPU` 覆盖。默认输出到项目内：

`outputs/episode_000000`

默认一个 60 Hz 轨迹帧对应一个隐式 IPC 步（`dt=1/60 s`，官方 Genesis IPC 示例使用 `dt=0.02 s`）。可用 `--substeps 2` 做更保守的 120 Hz 对照。

默认 `--drive-mode direct` 在每步直接设置插值 qpos，并关闭 IPC 到机器人的反向力，以严格保留公开轨迹；`--drive-mode pd --two-way-coupling` 可作为真实动力学跟踪消融，但不保证与记录 qpos 完全一致。

## 公平性边界

公开 SIM1 数据没有给出官方采集时的完整布料初态、抓取约束和全部物理参数。因此“同轨迹”可以严格保证，“同初态/同抓取”只能使用公开工程中可恢复的配置。Genesis 基线跑通后，应分别报告：自然摩擦抓取结果，以及若自然抓取失败时额外加入的显式附着约束结果，不能把两者混为一谈。

## 空间描述约定

项目讨论统一采用短袖自身作为参考，不采用画面左右、摄像头远近或机械臂左右
代替衣服方向：

- `上/下`：领口侧 / 腰摆侧；
- `左/右`：以穿衣者本人为准的短袖左袖 / 右袖；
- `正面/背面`：胸腹侧布料 / 后背侧布料；
- `高/低`：垂直桌面的高度；
- 机械臂只称 `机器人左臂/机器人右臂`，分别对应代码中的 `left_* / right_*`。

例如第二折前的问题应描述为：“机器人左臂前往短袖右袖侧时，高度不足，
擦碰并拖动了第一折折片。”

## 当前验证状态

- Genesis IPC 场景、Acone 轨迹与短袖网格已经跑通；
- 已用 SIM1 `sim2real.py`、Acone URDF 及独立指尖渲染交叉确认开合方向：
  归一化 `openness=1` / URDF `q=0.044` 为张开，`openness=0` / `q=0.001`
  为闭合；官方打包 action 的负号只属于数据存储变换；
- 先前生成的 `*_gripper_fixed.*` 实际做了多余反相，已移入输出目录下的
  `invalid_inverted_gripper_decode/`，只保留作错误诊断，不能用于物理结论。
  有效轨迹恢复为 `episode_000000_sim1_replay.npz`。在 `_init_qpos`/direct
  控制修复前生成的旧接触基线也已移入 `invalid_pre_direction_control_fix/`；
- Genesis IPC build 前所有活动关节的 `_init_qpos` 均保持 URDF 零点，首帧姿态
  只在 build 后用绝对 `set_qpos()` 设置；`direct` 模式不再与 PD controller
  叠加。独立测试实测 open/closed actual q 分别为 0.044/0.001 m。只把夹指
  归零仍不够：机械臂首帧若写入 `_init_qpos`，虽然 `get_qpos()` 看似正确，
  首次闭合附近左 TCP 的 FK 仍会产生约 21--22 mm 高度偏差；
- 已按上述修复重新完成 240 帧、无锚点、精确夹指碰撞的第一次抬升测试。
  闭合阶段第 90 帧左手目标 q=1.288 mm、实际 q=1.259/1.317 mm；第 150
  帧目标 q=0.854 mm、实际 q=0.798/0.910 mm，证明运行中的夹指也在正确方向
  且紧跟绝对目标，没有负 q 或越过对指。结果文件为
  `genesis_ipc_contact_grasp_first_lift_direction_control_fixed.{mp4,json}`；
- 原始位置基线未形成自然摩擦抓取：左右 TCP 最大分别抬升 164/160 mm，
  两个跟踪布片的最大抬升均为 0。通过对齐公开 Newton USD 中的抓点与 Genesis
  沉降后的同一批网格点，当前预设将衣服初始位置改为 `(0.667, 0.015, 0.93)`；
- Genesis 默认 `contact_d_hat=0.2 mm` 小于公开 SIM1 中夹指表面与抓点附近布料
  的 3--8 mm 间距。当前预设使用 5 mm，与 SIM1
  `lift2_short_shirt.py` 的 `cloth_body_contact_margin=0.005` 一致。配合位置对齐后，
  无锚点 IPC 摩擦抓取在 240 帧内将左/右跟踪布片最多抬升 163/112 mm，末帧
  仍抬升 160/87 mm；左手稳定，右手有约 49 mm 的累计相对滑移，尚需继续
  做抓点/指尖姿态校准；
- 2500 面结果中右手背面层会在抬升时脱爪，虽然正面层仍被夹住，但整条双层
  下摆失去横向张力，第一折释放后收缩成布团。根因之一是低模在抓取区严重
  丢失几何分辨率，而不只是普通的布料下垂；
- 8000 面模型保持相同轨迹和 IPC 参数后，240 帧内左/右跟踪布片最多抬升
  167/122 mm；380 帧第一折测试在第 332 帧正常释放，未再像 2500 面版本一样
  收缩成中央布团，但折片在放置阶段被夹爪向前压成多道横向褶皱。因此它只算
  “抓起和释放链路通过”，还不能算质量合格的第一折；
- 对第一折 TCP 轨迹的 FK 测量表明，桌面顶面为 `z=0.800 m`，放置末段右/左
  TCP 最低约为 0.826/0.851 m。新增可选参数 `--first-fold-tcp-lift`，通过 IK
  只抬高第一折放置段并保持 x/y 与工具姿态不变。提前加高 30 mm 的 8000 面
  消融仍出现同类横向褶皱，说明末端过低是加剧因素但不是主因；该参数默认仍为
  0，不会静默修改公开轨迹；
- 在上述消融基础上新增 `--first-fold-transfer-lift`：只在第一折横向搬运段
  增加净空，到目标附近再快速衰减，从而把原来的“边横移边下降”改成“高位
  横移 + 近似竖直放置”。配合 `table_friction=0.6`、最终放置净空 15 mm，
  8000 面版本不再把衣片持续推成多道手风琴式褶皱，并在约第 300 帧形成一条
  连续主折线。释放后折线仍明显回弹、右端仍不规整，说明轨迹过低是重要诱因，
  但剩余瓶颈仍包括右侧背层滑移、初态不一致，以及当前纯弹性布料模型缺少
  持久折痕。当前最佳结果可用 `./run_first_fold_improved.sh` 复现，输出为
  `genesis_ipc_first_fold_arc_improved_8000f.{mp4,json}`；
- 第二折准备段的 FK 检查显示，两臂都采用了低位斜向接近：机器人左臂从第
  348 帧的约 `z=0.899 m` 降到第 393 帧的约 `z=0.788 m`；机器人右臂随后从
  第 400 帧的约 `z=0.891 m` 降到第 439 帧的约 `z=0.774 m`。后者会先拨动
  第一折折片，再把折片与短袖下层同时夹住，造成第二折时整衣被带动。现分别
  提供 `--second-fold-left-approach-lift` 和
  `--second-fold-right-approach-lift`：左臂修正作用于第 340--393 帧，右臂
  作用于第 400--439 帧，均采用“高位横移 + 目标上方下降”，并在各自闭合帧
  恢复公开轨迹的原始抓取位姿；不改 x/y、末端姿态或夹爪开合时序。
  `./run_two_folds_improved.sh` 使用双臂 60 mm 最大净空和 8000 面短袖完成验证：
  两次接近都未再明显横向推动第一折折片，第二折抬升时未再把整件短袖同步
  拖走，短袖右袖和未折区域仍留在桌面；最终仍有弹性回弹与局部褶皱。输出为
  `genesis_ipc_two_folds_clear_approaches_8000f.{mp4,json}`；
- 对第二折右臂做进一步收紧：最大接近净空由 60 mm 提高到 80 mm，第 430 帧
  后才开始下降，并在第 439 帧闭合阈值处仍保留 24 mm 净空，到第 455 帧闭合
  稳定后才完全恢复公开轨迹。这是为了避免下降末段仍擦碰第一折折面，以及
  第一折折片和短袖下层被同时夹入；
- 第三折仅由机器人右臂执行（第 690 帧闭合、第 941 帧释放）。公开轨迹在接近
  时从第 640 帧约 `z=0.860 m` 降到第 690 帧约 `z=0.803 m`，闭合后还继续降到
  第 720 帧约 `z=0.773 m`，容易把夹爪压入多层布料。新增
  `--third-fold-right-grasp-lift`，在第 620--720 帧逐渐建立并保持 40 mm 净空，
  第 720--780 帧随公开轨迹自然抬升而平滑撤销。`./run_three_folds_improved.sh`
  会运行到第 980 帧并输出三折结果。纯 FK/IK 检查覆盖 216 个修正帧，最大
  末端误差约 0.10 mm。已在 RTX 5070 Ti 上完成 8000 面前台物理回放：980 帧
  耗时 610.45 s，平均约 1.61 FPS。第二折右臂的高位进场基本避开第一折折片，
  第二折能实际翻到短袖中部；第三折则未稳定夹住目标布层，右夹爪跟踪 patch
  距离从第 750 帧约 39 mm 墠到第 900 帧约 131 mm，后半段表现为压/扫布料，
  最终没有形成规整第三折。输出为
  `genesis_ipc_three_folds_improved_8000f.{mp4,json}`。下一步应优先修正第三折
  抓取位置/布层选择，而不是继续整体抬高搬运轨迹；
- 将右夹爪额外闭合补偿从 0.25 mm 增至 1.0 mm 后，240 帧右侧跟踪布片末端
  抬升由 116.2 mm 略降至 114.6 mm，没有改善双层夹持。问题不是法向夹紧力
  不足，而是背面层没有持续处于有效夹持接触拓扑中；
- 官方 Newton 初态使用 `CLOTH_POS.z=0.78`，比 `z=0.80` 的桌面顶面低约
  20 mm，并依靠 Newton 接触在运行时解穿透。Genesis IPC 不能接受该初态，
  当前迁移版把衣服抬到 `z=0.93` 后重新沉降；这会改变双层的相对位置、褶皱和
  残余应力。后续应优先从 Newton 导出解穿透后的粒子状态并迁移为 Genesis
  初态，再校准右侧抓取和少量放置高度，而不是继续盲调夹紧力或整体抬轨迹；
- 当前第一折结果为
  `genesis_ipc_contact_first_fold_8000f_380_overhead.{mp4,json}`。代码未启用
  `--virtual-grasp`，也没有绑定或改写布料节点。后续只输出 Genesis 本地单画面，
  不再生成视角和平台不一致的官方/本地拼接视频；
- 将壳厚升到 1 mm 会因双层网格局部间距仅约 1.26 mm 而被 IPC 初态检查
  拒绝，因此不能靠盲目加厚解决；
- 无锚点接触抓取的有效基线覆盖前 240 帧；
- 已在本地 IPC coupler 接入 libuipc `SoftPositionConstraint` 与运行时目标更新。测试表明 libuipc 必须在 world 初始化前预注册候选约束顶点；仅在闭爪时动态新增约束不会进入已构建的约束自由度集合。
- 第一折候选点已支持原网格与低模自动映射；后两折仍需从稳定的前序折叠状态导出候选点。
- 软位置约束在严格求解下仍有约 4--11 mm 滞后，没有把衣服可靠提离桌面；直接硬改节点在开启接触时会触发 IPC CCD 的负 TOI 断言。
- 无接触/无重力的硬绑定诊断已成功：240 帧内左右手分别保持 4/3 个低模节点，第 150 帧开始抬升，第 230 帧附近明显离桌；该结果仅代表运动学链路跑通。
